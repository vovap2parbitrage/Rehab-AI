# Rehab AI

Платформа дистанційної реабілітації. Лікар призначає пацієнту вправи, пацієнт виконує їх
вдома й записує відео, а AI порівнює рух з еталоном лікаря та повертає оцінку від 0 до 10
зі списком помилок. Лікар бачить історію виконання, біль і регулярність занять та відповідає
на запитання пацієнтів.

Стек: React-фронтенд, FastAPI backend, PostgreSQL, Redis, Celery та S3-сумісне сховище.
Усе запускається однією командою через Docker Compose.

## Швидкий старт

```bash
docker compose up --build -d
```

Після старту:

| Сервіс | Адреса |
| --- | --- |
| Вебзастосунок | http://localhost:3000 |
| API та Swagger UI | http://localhost:8001/docs |
| PostgreSQL | `localhost:5433` |
| Redis | `localhost:6380` |
| S3-сховище відео (RustFS) | `localhost:9000` |

Зареєструйтеся на `/register`: пацієнт і лікар обирають свою роль під час реєстрації.
Демо-акаунтів і адміністраторів немає.

Перевірити стан контейнерів:

```bash
docker compose ps
```

Зупинити стек:

```bash
docker compose down
```

Зупинити та видалити всі дані (БД, Redis, відео):

```bash
docker compose down -v
```

## Ролі й авторизація

Ролі зберігаються в таблиці `users` і читаються з БД на кожен запит, а не з токена.
Є лише дві ролі:

| Роль | Що може |
| --- | --- |
| Пацієнт | Приймати й відхиляти запрошення лікарів, бачити призначені вправи, виконувати їх із записом відео або без, ставити запитання лікарю, дивитися власну історію |
| Лікар | Запрошувати пацієнтів, вести бібліотеку вправ, призначати плани, дивитися історію пацієнтів, відповідати на запитання, архівувати й відновлювати пацієнтів, керувати тарифом |

На сторінці `/register` обирають «Пацієнт» або «Лікар»; роль активна одразу після
реєстрації, без підтвердження. Зміна ролі чи блокування облікового запису в БД діє на
наступний же запит.

Вхід і реєстрація повертають короткоживучий access JWT (15 хвилин) у відповіді. Він зберігається
лише в пам'яті браузера. Refresh-токен живе в cookie `HttpOnly; Secure; SameSite=Strict`,
зберігається в БД лише як SHA-256-хеш і обертається при кожному оновленні; повторне
використання старого токена завершує всю родину сесій. Cookie надсилається тільки на
`/api/v1/auth/*`, а запити з cookie захищені перевіркою `Origin`.

**Оновлення зі старої версії:** міграція `0014` видаляє всі старі облікові записи
та пов'язані дані, бо вони жили в зовнішньому сервісі й не мають паролів у цій БД. Після
оновлення потрібно зареєструватися заново.

## Тарифи для лікарів

Тариф обмежує кількість **активних** пацієнтів лікаря. Місце займають активні пацієнти та
запрошення, які ще очікують відповіді. Заархівований пацієнт у ліміт не входить.

| Код | Назва | Активних пацієнтів | Ціна |
| --- | --- | --- | --- |
| `free` | Безкоштовний | 5 | 0 ₴ / міс |
| `standard` | Стандарт | 15 | 499 ₴ / міс |
| `pro` | Професійний | 30 | 899 ₴ / міс |

Новий користувач починає з `free`. Коли ліміт досягнуто, запрошення пацієнта, прийняття
запрошення та відновлення з архіву повертають `409` із кодом `patient_limit_reached`.

Тарифи видно на публічній сторінці `/pricing` (посилання є у футері). Лікар змінює тариф
там само або в кабінеті. **Оплата тестова:** `PAYMENT_PROVIDER=mock` схвалює кожен платіж і
нічого не списує. Тариф діє, поки його не змінять, автопродовження немає.

Деталі API та ліміту: [`backend/README.md`](backend/README.md#тарифи-й-ліміт-активних-пацієнтів).

## Що входить до стеку

- `frontend` — збірка Vite у nginx, SPA fallback. Див. [`frontend/README.md`](frontend/README.md).
- `backend` — FastAPI + Uvicorn. Під час старту застосовує міграції БД
  (`alembic upgrade head`). Див. [`backend/README.md`](backend/README.md); створення міграції
  описано в розділі [«Міграції БД»](backend/README.md#міграції-бд-alembic).
- `celery-worker` — фоновий воркер для аналізу відео.
- `db` — PostgreSQL 16.
- `redis` — Redis 7 (брокер Celery).
- `s3` — S3-сумісне сховище відео (RustFS); `s3-init` створює бакет `rehab-videos`.

## Налаштування

Усі значення мають робочі типові значення. Щоб змінити порти, паролі або URL, створіть
`.env` із шаблону:

```bash
cp .env.example .env      # Linux, macOS, WSL
copy .env.example .env    # Windows (cmd, PowerShell)
```

Потім відредагуйте `.env` і перезапустіть:

```bash
docker compose up -d --build
```

`VITE_API_BASE_URL` вбудовується у фронтенд під час збірки, тому після його зміни потрібен
`--build`. `SECRET_KEY` використовується для підпису access-токенів: зміна ключа завершує
всі поточні сесії. Для HTTP на localhost лишайте `COOKIE_SECURE=false`; за HTTPS встановіть
`true`.

## Тести й перевірки

Обидва набори запускаються в CI (`.github/workflows`) на кожен push і pull request.

| Що | Команда | Де |
| --- | --- | --- |
| Тести фронтенда | `npm test` | `frontend/` |
| Типи, лінтер, формат, збірка | `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build` | `frontend/` |
| Тести фронтенда в Docker | `docker compose --profile test run --build --rm frontend-test` | корінь |
| Тести backend | `pytest -q` (потрібен PostgreSQL) | `backend/` |
| Міграції | `alembic upgrade head`, `alembic check` | `backend/` |

Подробиці та налаштування: [`backend/README.md`](backend/README.md#тести-та-ci) і
[`frontend/README.md`](frontend/README.md#тести).

## Безпека

Типові секрети (`SECRET_KEY`, паролі PostgreSQL і S3) призначені лише для локальної
розробки. Для production:

- згенеруйте випадковий `SECRET_KEY` (щонайменше 32 символи) і увімкніть `ENVIRONMENT=production`;
- увімкніть HTTPS і `COOKIE_SECURE=true`, інакше браузер не надішле refresh-cookie;
- не виставляйте застосунок без обмеження частоти запитів на зовнішньому балансуванні;
- замініть mock-платежі справжнім провайдером, перш ніж брати гроші за тарифи;
- зверніть увагу, що роль лікаря видається одразу після реєстрації: за потреби додайте
  перевірку лікарів (підтвердження пошти, ліцензія) до відкриття цієї можливості.
