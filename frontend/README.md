# AIRehab — вебфронтенд

React + TypeScript + Vite застосунок для пацієнтів і лікарів AIRehab: кабінет пацієнта,
кабінет лікаря, публічна сторінка тарифів. Вхід і реєстрація працюють безпосередньо з
FastAPI: пароль надсилається один раз у запиті, access-токен зберігається тільки в пам'яті,
а сесію відновлює HttpOnly cookie. Огляд продукту та запуск усього стеку:
[`../README.md`](../README.md).

## Вимоги

- Для локальних команд використовуйте Node.js `>=24.15.0 <25`. Цей діапазон відповідає
  налаштуванням CI та вимогам зафіксованих версій Vitest і jsdom.
- Для роботи застосунку потрібен FastAPI (http://localhost:8001 у Docker-стеку).

Найпростіший спосіб підняти все разом — `docker compose up --build -d` з кореня
репозиторію (див. [`../README.md`](../README.md)). Для запуску Vite на хості з API у
Compose налаштуйте [CORS](#backend).

## Команди

```bash
cd frontend
npm ci
npm run dev          # http://localhost:5173
npm run typecheck    # tsc -b
npm run lint         # oxlint
npm run format:check # prettier --check src
npm run build        # tsc -b && vite build
npm run preview      # http://localhost:4173
npm run test         # одноразовий запуск UI-тестів
npm run test:watch   # інтерактивний режим тестів
```

> У Windows PowerShell, якщо `npm` блокується політикою виконання, використовуйте `npm.cmd`.

## Тести

Тести написані на Vitest та React Testing Library й лежать у `src/test/`. Вони перевіряють:

- вхід і реєстрацію з вибором ролі, помилки сесії та збереження токена тільки в пам'яті;
- доступ за роллю та перенаправлення;
- кабінет пацієнта: запрошення, виконання вправ, запитання лікарю;
- кабінет лікаря: список пацієнтів, архівування й відновлення, призначення;
- сторінку тарифів (без входу, купівля для лікаря) і повідомлення про ліміт пацієнтів.

API підмінено, тому для запуску тестів не потрібно стартувати Docker чи backend.

```bash
cd frontend
npm ci
npm test
```

Для запуску одного набору тестів:

```bash
npm test -- src/test/patient-pages.test.tsx
```

### Запуск через Docker

З кореня репозиторію виконайте:

```powershell
docker compose --profile test run --build --rm frontend-test
```

Docker збере окремий тестовий образ і запустить тести в контейнері. `--rm` видалить
контейнер після завершення. Щоб передати Vitest параметри, наприклад запустити один файл:

```powershell
docker compose --profile test run --build --rm frontend-test npm run test -- src/test/patient-pages.test.tsx
```

У Windows PowerShell замініть `npm` на `npm.cmd`, якщо цього вимагає політика виконання.

## Змінні середовища

Значення за замовчуванням збігається з адресою API в Docker Compose. Щоб указати іншу
адресу, скопіюйте [`.env.example`](.env.example) у `frontend/.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:8001
```

| Змінна              | Призначення           |
| ------------------- | --------------------- |
| `VITE_API_BASE_URL` | Базова адреса FastAPI |

Vite читає це значення під час запуску dev-сервера та вбудовує його у збірку. Для збірки
через Compose адреса задається в кореневому `.env` через `VITE_API_BASE_URL`. Після зміни
адреси перебудуйте образ фронтенду.

## Потік автентифікації

- `POST /api/v1/auth/login` і `POST /api/v1/auth/register` приймають email і пароль і
  повертають профіль разом із короткоживучим access-токеном. Refresh-cookie встановлюється
  тими самими відповідями.
- Access-токен лежить у модулі `src/auth/session.ts` у пам'яті — ні `localStorage`, ні
  `sessionStorage` його не бачать. Перед запитом до API він перевіряється на термін дії;
  паралельні запити ділять один запит на оновлення.
- Після перезавантаження сторінки `AuthProvider` викликає `POST /api/v1/auth/refresh` і
  відновлює сесію з cookie. Якщо cookie немає, користувач вважається гостем; якщо сервер
  недоступний — показується окрема помилка з повторним запуском перевірки.
- Якщо API відповідає `401`, `apiRequest` один раз оновлює токен і повторює запит. Коли
  оновлення неможливе, сеанс завершується і захищені сторінки перенаправляють на `/login`.
- Роль, ім'я та статус беруться з `GET /api/v1/auth/me` і спільного стану `AuthContext`.
  Кнопка «Оновити дані» в профілі перечитує профіль; роль у меню змінюється одразу.
- `POST /api/v1/auth/change-password` у профілі змінює пароль і завершує сесії на інших
  пристроях. Вихід викликає `POST /api/v1/auth/logout`, який очищує cookie навіть якщо
  сервер недоступний.

Усі запити з refresh-cookie (`/auth/refresh`, `/auth/logout`) надсилаються з заголовком
`Origin`, який backend перевіряє; звичайні API-запити містять лише `Authorization: Bearer …`
і не надсилають cookie.

## Кабінет пацієнта

Кабінет завантажує запрошення, список терапевтів, призначення, історію виконання та
запитання до терапевта через API. Статус запрошення й виконані сесії зберігає backend.

Під час виконання вправи пацієнт може завантажити відео MP4 або MOV розміром до 100 МБ.
Фронтенд надсилає файл до S3-сумісного сховища за адресою від API та запитує фоновий
аналіз за еталонним відео вправи. Після успішного аналізу backend зберігає сесію з
результатом. Сесію також можна завершити без відео.

## Кабінет лікаря

Кабінет лікаря (`/therapist/*`) доступний лише ролі «лікар». Спільні дані (пацієнти,
архів, тариф, вправи) кешуються в `TherapistWorkspaceLayout` і оновлюються при поверненні
на сторінку.

- **Пацієнти.** Список активних пацієнтів, картка тарифу («активних 3 з 5, вільно 2»,
  очікувані запрошення займають місце) і форма запрошення за email пацієнта. Розділ «Архів»
  показує заархівованих пацієнтів із кнопкою «Відновити».
- **Профіль пацієнта.** Призначення плану (вправа, тижні, дні, повторення, дата початку),
  скасування призначень, запитання пацієнта й відповіді, історія виконання (біль,
  регулярність, оцінка техніки). Кнопка «Архівувати пацієнта» скасовує активні призначення
  лікаря для цього пацієнта; в архіві профіль доступний лише для читання, а форма
  призначення замінена повідомленням.
- **Вправи.** Бібліотека вправ: назва, опис, еталонне відео та частини тіла для аналізу.
  Допуски кутів форма не змінює, їх задають через API.
- **Запитання.** Усі запитання пацієнтів без відповіді; кількість показується біля пункту
  меню «Запитання».

Коли backend повертає `409` із кодом `patient_limit_reached`, `ApiError.code` містить цей
код, а користувач бачить пояснення, що ліміт тарифу вичерпано.

## Тарифи

Сторінка `/pricing` публічна: завантажує тарифи з `GET /api/v1/plans/` без токена
(`apiRequest` з `authenticated: false`). Незалогінений відвідувач бачить «Увійти, щоб обрати»,
лікар — свій поточний тариф і кнопки для інших тарифів, пацієнт кнопок не бачить. Оплата
тестова: тариф активується одразу, кошти не списуються. Посилання на сторінку є у футері та
в картці тарифу кабінету лікаря.

## Backend

Backend має дозволяти адресу фронтенду в `CORS_ORIGINS`: origins з цього самого списку
приймаються і для cookie-запитів `/auth/refresh` і `/auth/logout`. Compose за замовчуванням
дозволяє `http://localhost:3000`. Для Vite на хості створіть кореневий `.env` із
[`../.env.example`](../.env.example), якщо його ще немає. Додайте до списку `CORS_ORIGINS`
адресу `http://localhost:5173` (або `http://localhost:4173` для preview) і застосуйте
зміни командою `docker compose up -d backend`. Для запуску backend поза Compose див.
[`backend/.env.example`](../backend/.env.example). Запити до API авторизуються заголовком
`Authorization: Bearer …`; за HTTPS cookie стає `Secure` (у локальному Compose він
вимкнений, бо сторінка відкривається за HTTP).
